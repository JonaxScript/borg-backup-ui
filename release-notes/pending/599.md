### Bug Fixes

- Keep the Restore Test memory group alive until final counters are checked, preventing false failures when Unraid automatically removes empty groups after worker exit. Missing final memory counters still fail verification, and cleanup errors no longer hide the original failure. (#599)
- Reduce Restore Test memory consumption for archives with millions of files by streaming file lists while preserving full L2 verification and existing sampling rules. (#599)
- Report timed-out full dry-runs and failed metadata checks as failures instead of successful verification. (#599)

### Improvements

- Add configurable Restore Test memory protection covering the worker and Borg children, monitored host headroom, and sequential execution of protected tests. Preserve per-run reports and log references after retries. (#599)

### Migration and compatibility

- Restore Tests default to a 2048 MiB memory budget and a 1024 MiB host reserve, including existing installations. Protected tests require a writable cgroup v2 memory controller with cgroup.kill and permission to protect the idle keeper from OOM killing and fail with a clear report if enforcement is unavailable. Setting the memory limit to 0 explicitly disables protection, the reserve check and sequential execution. No backup data or existing configuration is overwritten. (#599)
